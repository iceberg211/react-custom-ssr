服务端渲染阶段
🖥️ SSR渲染流程
1
Koa服务器接收请求
文件： app/server/server.ts
Koa服务器监听端口，接收所有路由请求 router.get('(.*)')
const app = new Koa(); const router = new Router(); router.get('(.*)', async (ctx) => { // SSR逻辑 });
2
初始化ChunkExtractor
文件： app/server/index.tsx
加载loadable-stats.json，用于收集渲染过程中使用的代码块
const extractor = new ChunkExtractor({ statsFile: './loadable-stats.json', entrypoints: ['client'] });
3
路由匹配与数据预取
文件： app/server/app.tsx - prefetch()
使用react-router-dom的matchRoutes匹配路由，执行数据预取逻辑
const prefetchRoutes = matchRoutes(routes, ctx.req.url); await Promise.allSettled( prefetchRoutes.map(({ route }) => route.queryKey && queryClient.prefetchQuery({ queryKey: route.queryKey, queryFn: () => route.loadData() }) ) );
4
创建React组件树
文件： app/server/app.tsx - renderApp()
使用StaticRouter、QueryClientProvider、HelmetProvider包裹App组件
const jsx = extractor.collectChunks( <StaticRouter location={ctx.req.url}> <HelmetProvider context={helmetContext}> <QueryClientProvider client={queryClient}> <HydrationBoundary state={dehydratedState}> <App context={ctx} /> </HydrationBoundary> </QueryClientProvider> </HelmetProvider> </StaticRouter> );
5
流式渲染HTML
文件： app/server/stream/response.ts
使用React 18的renderToPipeableStream进行流式SSR，分阶段输出HTML
const { pipe } = renderToPipeableStream(jsx, { onShellReady() { ctx.res.write(getStartTemplate(...)); }, onAllReady() { pipe(ctx.res); ctx.res.end(getEndTemplate(...)); } });
6
注入脱水状态和资源
文件： app/server/htmlTemplate.ts
在HTML中注入：
✓ React Query脱水状态 (__REACT_QUERY_STATE__)
✓ SSR标识 (__APP_FLAG__)
✓ CSS链接和样式标签
✓ JS脚本标签（包含代码分割的chunks）
✓ Helmet生成的meta标签
7
返回完整HTML给浏览器
浏览器接收到完整的HTML页面，包含已渲染的React内容和所有必要的资源引用

客户端水合阶段
💧 Hydration流程
1
浏览器解析HTML
浏览器接收并解析服务端返回的HTML，展示服务端渲染的内容（此时页面已可见但不可交互）
2
加载JavaScript资源
浏览器按顺序加载：
✓ runtime chunk（Webpack运行时）
✓ vendor chunks（第三方库）
✓ main chunk（应用主代码）
✓ 异步chunks（按需加载的代码）
3
读取脱水状态
文件： app/client/index.tsx
从HTML中读取两个关键script标签的内容
const getDehydratedState = () => { const element = document.querySelector('#__REACT_QUERY_STATE__'); return JSON.parse(element.textContent); }; const getTradeFlag = () => { const element = document.querySelector('#__APP_FLAG__'); return JSON.parse(element.textContent); };
4
等待Loadable准备就绪
使用@loadable/component的loadableReady()，确保所有代码分割的chunks都已加载完成
if (tradeFlag.isSSR) { loadableReady(() => { hydrateRoot(root, <ClientApp />); }); }
5
执行React Hydration
根据SSR标识选择渲染方式：
SSR模式：使用hydrateRoot()进行水合
CSR模式：使用createRoot().render()直接渲染
const ClientApp = () => ( <BrowserRouter> <HelmetProvider> <QueryClientProvider client={queryClient}> <HydrationBoundary state={dehydratedState}> <App /> </HydrationBoundary> </QueryClientProvider> </HelmetProvider> </BrowserRouter> );
6
恢复应用状态
React Query使用HydrationBoundary将服务端的状态恢复到客户端QueryClient，避免重复请求
7
激活交互功能
水合完成后，React接管DOM，绑定事件监听器，应用变为完全可交互状态
🔄 双模式支持
  • SSR水合模式
  • CSR渲染模式

数据流转机制
🔄 数据预取与同步
1
路由配置数据预取
文件： src/routes/index.tsx
路由配置中定义queryKey和loadData函数
const routes = [ { path: ':locales/home', element: <Home />, queryKey: [PrefetchKeys.HOME], loadData: HomeService.getList } ];
2
服务端数据预取
在SSR过程中，根据匹配的路由执行对应的loadData函数，使用React Query的prefetchQuery预取数据
await queryClient.prefetchQuery({ queryKey: route.queryKey, queryFn: () => route.loadData(params) });
3
状态脱水（Dehydration）
使用React Query的dehydrate函数将QueryClient中的所有查询状态序列化为JSON
const dehydratedState = dehydrate(queryClient); const stateJSON = JSON.stringify(dehydratedState);
4
注入到HTML
将脱水后的状态通过script标签注入到HTML中，ID为__REACT_QUERY_STATE__
<script id="__REACT_QUERY_STATE__" type="application/json"> ${dehydratedState} </script>
5
客户端状态水合（Hydration）
客户端读取script标签中的状态，通过HydrationBoundary组件恢复到QueryClient
<HydrationBoundary state={dehydratedState}> <App /> </HydrationBoundary>
6
组件使用数据
组件中使用useQuery hook，由于状态已经存在于QueryClient，不会触发新的请求
const { data } = useQuery({ queryKey: [PrefetchKeys.HOME], queryFn: HomeService.getList }); // 数据来自服务端预取，无需重新请求
